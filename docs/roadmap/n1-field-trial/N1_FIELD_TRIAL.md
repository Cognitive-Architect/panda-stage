# N1｜实战取样与主要阻塞修复

> 路线图用途：定义 N1 的执行边界、验收方式与止损条件；**不作为实时项目状态页**。实际执行状态以 GitHub live state、最新 MasterMind / maintainer receipt 为准。本文件本身不授权代码改动或后续 N2 施工。

**阶段目标：**不再重复逐功能演示，而是从空项目完成 10～15 秒双人对白项目，交付真实摩擦账本。[R §5]

**进入条件：**采用 Day29 后已接受的可用版本；维护者授权本次采样。**离开条件：**当前承诺范围内的编辑、分镜头预览、保存重开成立，严重阻塞没有被隐藏。

**明确不做：**本阶段不要求 MP4、不要求一次连续播放所有镜头、不临时加入状态系统或动作系统；采样过程中不改代码。未来缺少的表达能力要记录，但不伪装成已承诺功能的故障。

### N1-01｜固定小作品与真实运行基线

**类型 / 风险：**采样准备 / 低。**前置：**维护者授权，无其他任务编号阻塞。

**本次成果：**一份可以立即开始的作品任务单和空回执，不替主理人自动做作品。

| 序 | 任务 | 责任区域 | 实施细节 |
|---:|---|---|---|
| 1 | 记录实际版本 | 运行环境 / 交付记录 | 对上源码 HEAD、运行应用路径/构建信息，防止验旧包；记录窗口、DPI、输入方式 |
| 2 | 固定作品规格 | 采样任务 | 10～15 秒、2 角色、2 镜头、至少 6 行对白、至少 4 段真实音频；不临时减少难度 |
| 3 | 准备输入素材 | 素材准备 | 原创或获准使用的图与配音，注明来源；素材准备耗时与编辑耗时分开 |
| 4 | 约定观察方式 | 验收记录 | 录屏或逐步记录；计时、求助、绕路、无法表达四类均能记录；不收集无关隐私 |
| 5 | 建立接管目录 | 本地辅助工具 | 自动生成版本与空模板；正式项目仍由真人在正常界面新建 |

**UI/UX：**只记录现有入口和被测条件，不在采样前先把不顺眼的地方改掉。按 UX-09 固定实际设备条件。

**自动验证（V-DOC）：**检查任务单数字和材料清单齐全；已记录的版本来源可追溯；输出目录是新建且不覆盖旧证据。不运行产品全量测试。

**人工确认：**启动实际 Electron 应用；确认能进入空项目创建路径；确认素材与剧本足以完成规定范围。不能识别运行版本时先澄清，不开始正式计时。

**交付与完成：**任务单、素材来源说明、版本/环境记录、空摩擦记录；维护者认可后可进入 N1-02。未制作作品，不写 Creator Gate PASS。

**止损：**素材许可不明则仅限明确允许的私人研究并记录，不能进入可分发样例；样本不足或运行版本不明时停在准备状态。**后继：**N1-02。

### N1-02｜从空项目完成一次不插代码的制作

**类型 / 风险：**真人生产采样 / 中。**前置：**N1-01。

**本次成果：**第一段真实项目和制作记录，证明能否通过正式界面做出来。

| 序 | 任务 | 责任区域 | 实施细节 |
|---:|---|---|---|
| 1 | 新建并搭镜头 | 正式项目 / 角色 / 镜头 / 画布 | 从空项目建立 2 角色、2 镜头；不复制已完成工程 |
| 2 | 录入并安排对白 | 字幕工作区 / 时间轴 | 至少 6 行；实际使用手动拖入或自动加入，记录选择原因与阻碍 |
| 3 | 绑定真实配音 | 当前属性 / AudioClip | 至少 4 段；按需要裁剪或恢复可用长度；不假造音频时长 |
| 4 | 查看实际结果 | 当前单镜头预览 | 两个镜头分别完整播放；检查说话人、字幕、声音、简单嘴型；不声称整项目连播 |
| 5 | 保存与恢复工作 | 正式保存 / 打开路径 | 保存、关闭项目、重开，再查看镜头内容与预览；不得手改文件补救 |

**UI/UX：**观察画布是否可见、列表是否连续、时间编辑是否好抓、配音是否容易找到。主理人不知道下一步时记录求助，不把执行者口头导航省略掉。

**自动验证（V-DOC）：**辅助计时/文件清单/录屏时间戳可自动整理；只检查记录缺项，不自动把缺项填 PASS。项目数量可通过已支持的只读检查辅助，但不能代替真人路径。

**人工验收：**依次完成上表全部正式 UI 步骤；记录分镜头预览及重开结果；每次卡住写下原本想做什么、实际做法、能否继续。无法完成就保留受阻工程与复现，不删剧情制造成功。

**交付与完成：**项目、操作记录、主动时间/等待时间、求助与摩擦列表；结果允许 PASS 或 FAIL，真实受阻的采样也算采样任务完成，但阶段仍可能未通过。

**止损：**作品丢失、异常覆盖、跨项目污染时立即停止并保留副本；不在本轮边演示边修。**后继：**N1-03。

### N1-03｜把摩擦变成最小修复与未来需求

**类型 / 风险：**归纳＋设计 / 低。**前置：**N1-02。

**本次成果：**有证据的修复批次，以及不抢当前主线的表达需求清单。

| 序 | 任务 | 责任区域 | 实施细节 |
|---:|---|---|---|
| 1 | 区分三种问题 | 摩擦账本 | 功能坏了、操作太累、尚无表达能力；不要统统写成 P0 |
| 2 | 合并同根因问题 | 复现与优先级 | 引用截图/步骤；判断是否版本错误、操作误解、真实缺陷或设计缺口 |
| 3 | 选择修复批次 | 当前 N1 范围 | 每批最多 3 个最影响已承诺作品的问题；其他严重问题仍保留为阻挡，不丢弃 |
| 4 | 写清 UI 修复意图 | 涉及的现有界面 | 必要时先出文字方案/概念；指出入口、主动作、提交/取消与不改项，等待确认 |
| 5 | 留下未来价值证据 | N4/N5/N6 输入 | 记录换表情、套动作、部件对齐等重复次数与无法表达的意图，不先决定实现 |

**UI/UX：**按 UX-01/11 确认修复设计；不得用新一轮全局美化替代对具体失败路径的解决。

**自动验证（V-DOC）：**每个入选问题有复现与预期；每个设计变化有确认状态；既有问题没有在排序后消失。未计算的耗时留空，不填估值。

**人工确认：**主理人检查“这是不是当时卡住的事情”；确认最小修复范围。没有主要阻塞则明确 N1-04 仅做收口复核，不硬造三项修改。

**交付与完成：**带来源的主要问题、已批准或待批准的局部方案、未来能力候选；不以这一张排序表替代产品已经修复。

**止损：**若修复开始需要整套通用动作、另一套属性区或第二播放时钟，缩回真实问题并重新说明范围。**后继：**N1-04。

### N1-04｜修一批、复走受影响路径、关闭 Gate A

**类型 / 风险：**有条件实施＋验收 / 取决于入选问题，最高按数据影响评估。**前置：**N1-03；涉及 UI 的方案先确认。

**本次成果：**同一作品能在当前承诺范围内完成，而不是只得到一份修复代码。

| 序 | 任务 | 责任区域 | 实施细节 |
|---:|---|---|---|
| 1 | 锁定修复与测试范围 | 当前问题实际模块 | 给出实际代码/测试路径与受影响合同；不因修一处而考古全仓 |
| 2 | 逐项修复 | 已批准问题链路 | 先处理作品安全和阻断；一次完成一个可复验问题；无问题则不改代码 |
| 3 | 运行相关检查 | 模型 / 交互 / 正常 CI | 补直接回归；保留当前画布/时间轴/保存职责；不手动 Full |
| 4 | 复走并比对 | Windows/Electron | 使用修复版本复走受影响步骤；有布局变化集中看一次，必要时一批修正后再确认 |
| 5 | 结账 | 阶段回执 | 分列自动、真人、维护者及合并状态；保留尚无证据的限制 |

**UI/UX：**只验已批准目标，不把“还能更漂亮”继续加入；同一页面过度拥挤、按钮假编辑、画布被遮等实际阻碍不能被自动绿灯掩盖。

**自动验证：**对每个已修根因运行最小相关测试；涉及模型的验证无效输入/撤销/保存；涉及 UI 的验证当前入口可达、动作有效。只采样无改动时开发检查 N/A。

**人工验收：**核对确实运行修复版；复走原失败路径并完成保存重开；两个镜头分别完整预览。复用未受影响且条件相同的证据，不要求重演全部 Day29。

**交付与完成：**问题前后结果、实际版本、可复现项目、Gate A 结论。没有未处理的作品安全/核心路径阻塞才可作为 N2 前置；有限接受必须注明边界。

**止损：**同批修复造成直接回归则暂停推进；出现新根因保留证据另行处置，不无限扩成“顺便修完”。**后继：**获授权后进入 N2-01。
