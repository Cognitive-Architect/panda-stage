# N1-04｜修一批、复走受影响路径、关闭 Gate A

> 来源：N1～N7 分阶段执行计划 v1.1。状态字段只表示本路线图任务定义，不替代实时 GitHub / MasterMind 状态；实际执行前仍需核对当时仓库、依赖和维护者授权。

## 所属阶段与边界

**阶段目标：**不再重复逐功能演示，而是从空项目完成 10～15 秒双人对白项目，交付真实摩擦账本。[R §5]

**进入条件：**采用 Day29 后已接受的可用版本；维护者授权本次采样。**离开条件：**当前承诺范围内的编辑、分镜头预览、保存重开成立，严重阻塞没有被隐藏。

**明确不做：**本阶段不要求 MP4、不要求一次连续播放所有镜头、不临时加入状态系统或动作系统；采样过程中不改代码。未来缺少的表达能力要记录，但不伪装成已承诺功能的故障。

## 本卡执行内容

**类型 / 风险：**有条件实施＋验收 / 取决于入选问题，最高按数据影响评估。**前置：**N1-03；涉及 UI 的方案先确认。

**本次成果：**同一作品能在当前承诺范围内完成，而不是只得到一份修复代码。

| 序 | 任务 | 责任区域 | 实施细节 |
|---:|---|---|---|
| 1 | 锁定修复与测试范围 | 当前问题实际模块 | 给出实际代码/测试路径与受影响合同；不因修一处而考古全仓 |
| 2 | 逐项修复 | 已批准问题链路 | 先处理作品安全和阻断；一次完成一个可复验问题；无问题则不改代码 |
| 3 | 运行相关检查 | 模型 / 交互 / 正常 CI | 补直接回归；保留当前画布/时间轴/保存职责；不手动 Full |
| 4 | 复走并比对 | Windows/Electron | 使用修复版本复走受影响步骤；有布局变化集中看一次，必要时一批修正后再确认 |
| 5 | 结账 | 阶段回执 | 分列自动、真人、维护者及合并状态；保留尚无证据的限制 |

**UI/UX：**只验已批准目标，不把“还能更漂亮”继续加入；同一页面过度拥挤、按钮假编辑、画布被遮等实际阻碍不能被自动绿灯掩盖。

**自动验证：**对每个已修根因运行最小相关测试；涉及模型的验证无效输入/撤销/保存；涉及 UI 的验证当前入口可达、动作有效。只采样无改动时开发检查 N/A。

**人工验收：**核对确实运行修复版；复走原失败路径并完成保存重开；两个镜头分别完整预览。复用未受影响且条件相同的证据，不要求重演全部 Day29。

**交付与完成：**问题前后结果、实际版本、可复现项目、Gate A 结论。没有未处理的作品安全/核心路径阻塞才可作为 N2 前置；有限接受必须注明边界。

**止损：**同批修复造成直接回归则暂停推进；出现新根因保留证据另行处置，不无限扩成“顺便修完”。**后继：**获授权后进入 N2-01。
