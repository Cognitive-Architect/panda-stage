## F1 · R6 嵌套解组不重复吸收父级矩阵 — 成立并已修

- **根因**：`remapInstanceTransformFrameMaps` 把被移除 Group 的有效矩阵合成进**所有** `[groupId, ...]` 深度 > 1 的实例覆盖；实际只有被提升为直接子节点的路径（长度 2）需要吸收，孙节点路径的存活父节点已携带该矩阵，再合成一次即重复。
- **修复**：合成条件改为仅直接子节点（`parsed.length === 2`）；更深层覆盖只重键；「仅覆盖了组」的合成块仍只写直接子键。
- **反例数值**：外组 X=100 + 内组 X=20 + 孙覆盖 X=30 → 修复前孙节点世界 X=**250**（覆盖被存成 130），修复后 **150**；组覆盖 1000 + 直接子覆盖 7 + 孙覆盖 30 → 2037 → **1037**；非单位缩放/旋转组合修复后 6 个矩阵分量与解组前一致。
- **测试**：`tests/unit/fla-review-1469.test.ts`（5）——仅孙覆盖、仅组覆盖、组+直接子+孙、非单位缩放旋转、其他帧/共享定义/无关实例不回归。
- **限制**：未扩大 ungroup 支持范围；动画/遮罩/拆分区域/帧裁剪仍明确拒绝。

## F2 · R2 跨工程导入不自动公开实例私有动作 — 成立并已修

- **根因**：`remapCharacterActions` 在「目标工程恰好存在同 id 图层」时才保留 `instanceScope`；正常导入时该条件为假，于是丢掉 `instanceScope`/`originActionId` 却保留私副本的修改轨道，并给私副本新分配 id，把它当作普通共享动作导入（同时 `motionMappings.sourceActionId` 继续指向该升格副本）。
- **修复**：以实例隔离为默认语义——只有共享动作进入目标角色动作库；私副本沿 `originActionId` 链解析真实共享 origin（带环保护），可导入时以 alias 映射到 origin 的目标 id 供 `motionMappings` 使用；origin 缺失时相关 mapping 整条丢弃；不再用「目标存在同 id/同名图层」推断 owner（该启发式已删除）；所有动作被排除时省略 `actions` 字段。
- **测试**：`character-action-instance-scope.test.ts` 4 条（1 条旧 promotion 断言改写 + 3 条新增）——不升格、不据同 id 图层推断、引用重映射到共享 origin、origin 缺失时降级；`project-resource-import-bones.test.ts` 旧断言同步改为隔离语义。
- **限制**：「私有修改公开复用」按票面排除项未实现。

## F3 · R8 多末端锁定保护高优先级祖先并报告最终残差 — 成立并已修

- **根因**：① `claimed` 只记录实际求解的 ≤3 根骨，较浅的后续锁定仍可旋转更早已解算链的**祖先**（`Root→A→B→C→D→E` + `A→F→G`：E 占 B/C/D，G 经 F→A 旋转 A），悄悄移动已解算末端，而旧残差在此之前算出且不再更新；② 残差在循环内逐锁计算，evaluator 的第二次父空间后处理之后还会再变，返回残差与最终 layers 不一致。
- **修复**：新增 `frozenAncestors`——锁定成功后冻结「最上层已解算骨骼之上的完整祖先路径（排除 root）」，后续 movable chain 命中即按既有优先级 `shared-ancestor` 降级；循环内只记结构原因（`invalid-target`/`invalid-chain`/`shared-ancestor`），循环结束后用**最终 FK** 重算全部有效锁残差并替换（不保留旧值）；evaluator 在两次父空间 pass 之后按最终 pose 与最终 `parentSpace` 重算。
- **反例数值**：可达场景 E 目标 (500,290) → 修复前 E 实际 (525.94,287.40)（误差 26.07）且无 residual，修复后 (500.000,290.019)（0.019）且 G 报 `shared-ancestor` 56.57；不可达场景 E 真实误差 185.98 而返回旧值 180.00 → 修复后真实误差 180.00 与返回一致；父空间三层挂接：返回 1244.85 vs 真实 2182.10 → 修复后返回 2182.103。
- **独立双腿仍可同时求解**：左右脚目标同时写入后两脚误差均 ≤0.75、`residuals=[]`、未解算 PELVIS。
- **测试**：`character-end-effector-lock-ancestor.test.ts`（5）+ 原锁/非等比/R1 遮罩回归。
- **限制**：evaluator 仍最多 2 次父空间 pass（三层不收敛时残差真实但未达目标）；冻结规则按既有优先级收紧，属有意语义。

## F4 · R3 曲线遮罩填充转换不误判等价 — 成立并已修

- **根因**：fill-rule 归一化把每段 Bézier 扁平化为最多 12 段折线做自交/互交/包含判定，却输出**原始曲线**路径——折线是近似而非等价证明，真实曲线可在采样之间交叉，导致错误反转 winding 后仍声明等价。
- **修复**：彻底删除采样；纯直线（多边形）轮廓走原精确判定；曲线只在可精确证明时原样输出——① 整张遮罩仅 1 个 coverage 贡献（原样 authored 路径 + authored fillRule），② 多个同 fillRule 贡献且保守精确包围盒两两严格不相交；其余曲线 region 报 typed `unsupported-curve-fill-rule` 并按 R3 既有语义局部降级（其他 region/遮罩/图层继续工作）。单次 clip 的规则由 domain 在 `CoverageMaskClip.fillRule` 给出，Editor 与 Stage/Preview/Export 共用同一 `clipFunc`。
- **反例**：`M 0 1500 Q 600 -1500 1200 1500` + 矩形 x553..557,y7..10 跨真实曲线、折线不相交 → 修复前 `convertCoverageRegionToNonzero` 返回 `ok:true` 并输出原曲线、规则 `nonzero`、witness (555,9) 被填充；修复后 `ok:false` + `unsupported-curve-fill-rule`，规则为 authored `evenodd`、路径为 authored 曲线逐字，witness 不被填充。
- **测试**：`coverage-mask-geometry.test.ts` 新增 8 条（反例拒绝、单曲线 evenodd 原样、nonzero 反向绕向孔洞、evenodd 曲线孔洞、可证不相交的 nonzero 曲线、可证不相交的 evenodd 曲线、重叠曲线 typed 降级、混合规则局部降级）+ `stage-coverage-mask.test.ts` 1 条（Konva 单一 clip 使用解析出的规则）。
- **新增降级边界**：包围盒重叠的多曲线 region、曲线 region 与其他 region 包围盒重叠、evenodd 曲线 region 与其他 region 共存时按 `unsupported` 局部降级（单次 clip 只能一个规则）；单曲线 region、同规则且可证 bbox 不相交的多曲线、纯多边形、空覆盖/不支持/图像足迹语义保持。
- **限制**：曲线跨区域合并/转换需真实曲线布尔或真实填充合成，本票明确不自研布尔引擎，故上述场景局部降级；遮罩图形内部 FLA `clipPaths` 不参与覆盖求交（既有 F07 边界）；path 4 位小数量化为既有矢量管道行为。
