## 收口规则

1. 只记录真实观察，不把“也许会有问题”写成已知缺陷。
2. 每条问题必须能回答：哪里不对、怎么复现、预期是什么。
3. P0/P1 原则上单独开 Issue；P2/P3 可先留在本台账，积累到合适批次再切实施单。
4. 修复完成后必须回到实机复验，不能只凭 CI / 单测改成 FIXED。
5. 如果某条问题其实属于 #233 Day29，则只做交叉引用，不在这里偷偷接手 #233。

## Definition of Done

- 没有未归类的 P0/P1；
- 所有标记 FIXED 的问题都有真人实机复验；
